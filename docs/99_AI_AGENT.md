# 99_AI_AGENT.md

# AI Agent Development Guide

Project Psychology AI Lab

Version 1.0.0

Status Required

---

# Purpose

This document defines the mandatory development rules for AI coding agents contributing to Psychology AI Lab.

It provides a consistent workflow, architectural constraints, implementation priorities, and quality standards to ensure that code generated by different AI agents remains compatible, maintainable, and aligned with the project's long-term vision.

This document should be treated as the primary operational guide for AI-assisted development.

---

# Primary Mission

The mission of the AI coding agent is to

 Implement specifications faithfully.
 Preserve architectural integrity.
 Avoid unnecessary complexity.
 Maintain reproducibility.
 Produce readable, maintainable code.
 Never sacrifice long-term quality for short-term convenience.

The AI agent should behave as an implementation engineer, not as a product designer.

---

# Source of Truth

When implementing features, follow this priority order

1. This document (`99_AI_AGENT.md`)
2. `91_DEVELOPMENT_ORDER.md`
3. `90_IMPLEMENTATION_ROADMAP.md`
4. Architecture documents (`00–42`)
5. Existing source code

If implementation conflicts with documentation, documentation takes precedence unless explicitly superseded.

---

# Development Workflow

For every task

1. Read the relevant specification documents.
2. Identify dependencies.
3. Implement the smallest complete feature.
4. Write tests.
5. Run formatting and linting.
6. Verify that existing behavior is unchanged.
7. Update documentation if required.
8. Commit only logically complete changes.

Never skip intermediate steps.

---

# Architecture Rules

The AI agent shall preserve the following layers

```text
Presentation

↓

Application

↓

Domain

↓

Infrastructure
```

Rules

 Never place business logic in the Presentation Layer.
 Never call infrastructure directly from the UI.
 Keep the Domain Layer framework-independent.
 Depend on interfaces, not implementations.
 Maintain clear separation of concerns.

---

# Scope Control

Implement only the requested feature.

Do not

 Add unrelated functionality.
 Perform speculative refactoring.
 Introduce new dependencies without justification.
 Change APIs unless required.
 Modify database schemas unnecessarily.

Small, focused changes are preferred.

---

# Coding Standards

Generated code shall

 Be readable.
 Be modular.
 Be strongly typed where applicable.
 Follow the project's Code Style Guide.
 Avoid duplication.
 Prefer composition over inheritance.

Code should optimize for maintainability rather than brevity.

---

# Testing Policy

Every functional change should include appropriate tests.

Recommended order

1. Unit Test
2. Integration Test
3. API Test
4. Benchmark Test (when applicable)

Never introduce a feature that cannot be reasonably tested.

---

# Documentation Policy

Documentation shall remain synchronized with implementation.

Update documentation whenever

 APIs change
 Database schema changes
 Configuration changes
 User workflows change
 Public behavior changes

Do not leave documentation outdated.

---

# Benchmark Integrity

Psychology AI Lab is a scientific research platform.

Therefore

 Do not modify published benchmark datasets.
 Do not alter historical benchmark results.
 Preserve reproducibility.
 Record versions for datasets, prompts, personas, scoring rules, and configurations.
 Treat benchmark outputs as research evidence.

---

# AI Provider Rules

All provider-specific logic shall remain inside the Provider Manager.

The Benchmark Engine must never depend directly on

 OpenAI SDKs
 Gemini SDKs
 Anthropic SDKs
 OpenRouter APIs

All communication shall pass through provider adapters.

---

# Error Handling

Errors shall

 Be explicit.
 Be typed.
 Include meaningful messages.
 Avoid exposing secrets.
 Preserve stack traces where appropriate.

Silent failures are prohibited.

---

# Security Rules

Never

 Hard-code API keys.
 Commit secrets.
 Log sensitive credentials.
 Disable authentication for convenience.
 Bypass validation.

Use environment variables or secure secret management.

---

# Database Rules

The AI agent shall

 Use migrations for schema changes.
 Preserve referential integrity.
 Avoid destructive updates.
 Respect versioning rules.
 Treat published records as immutable.

Never rewrite historical research data.

---

# Git Policy

Each commit should

 Solve one logical problem.
 Be independently reviewable.
 Preserve a working build.

Recommended commit sequence

 Infrastructure
 Domain
 Services
 API
 Frontend
 Tests
 Documentation

---

# Performance Guidelines

Prefer

 Simplicity
 Predictability
 Maintainability

Optimize only after identifying measurable bottlenecks.

Avoid premature optimization.

---

# Refactoring Rules

Refactoring is permitted only when it

 Improves readability.
 Removes duplication.
 Simplifies architecture.
 Preserves behavior.

Behavioral changes require explicit justification and corresponding tests.

---

# Definition of Done

A task is complete only when

 Implementation matches the specification.
 All relevant tests pass.
 Linting succeeds.
 Formatting is applied.
 Documentation is updated.
 No critical issues remain.
 The project builds successfully.

# Relationship with AIMindary

Psychology AI Lab and AIMindary have distinct responsibilities.

Psychology AI Lab

 Research
 Benchmarking
 Evaluation
 Validation
 Package Generation

AIMindary

 Production Counseling
 User Sessions
 Memory
 Personalization
 Continuous User Support

The AI agent shall not blur the boundary between research and production systems.

# Guiding Philosophy

Every implementation decision should support the following goals

 Scientific rigor
 Reproducibility
 Transparency
 Modularity
 Maintainability
 Extensibility
 Clinical responsibility

The platform exists to generate trustworthy evidence, not merely functional software.

# Summary

This document defines the operational rules for AI coding agents working on Psychology AI Lab.

By establishing a consistent development workflow, strict architectural boundaries, testing requirements, documentation policies, and research-oriented engineering principles, it ensures that code generated by different AI agents remains coherent, reliable, and scientifically reproducible. Following these guidelines allows Psychology AI Lab to evolve as a high-quality research platform while providing validated components for deployment into AIMindary.
